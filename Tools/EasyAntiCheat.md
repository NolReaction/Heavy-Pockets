# Easy Anti-Cheat в Heavy Pockets

## Для владельца продукта

1. Войдите в [Epic Developer Portal](https://dev.epicgames.com/portal/) в своей организации. Создайте или выберите **Heavy Pockets**, затем тестовое развёртывание (deployment). Решение о принятии условий Epic принимает владелец организации.
2. Включите Anti-Cheat для продукта. Настройте и активируйте Windows-модуль для тестового развёртывания. Создайте отдельные политики и креденшелы игрового клиента и доверенного выделенного сервера. Для входа игроков используйте EOS Connect и связанный Epic-аккаунт. [Интерфейсы и требования Epic](https://dev.epicgames.com/docs/epic-online-services/trust-and-safety/anti-cheat-interfaces/anti-cheat-interfaces).
3. В Build/Protected/Client/EasyAntiCheat скопируйте Settings.template.json в Settings.json и заполните productid, sandboxid и deploymentid своего тестового окружения. Укажите файл клиента **HeavyPockets.exe**. Установку службы на тестовом ПК выполняет уполномоченный администратор штатным установщиком Epic. Активируйте проверку целостности и подготовьте её данные по инструкции для своей версии SDK. [Руководство по настройке](https://dev.epicgames.com/docs/epic-online-services/trust-and-safety/anti-cheat-interfaces/using-anti-cheat).
4. Проведите приёмку с защищённым клиентом на отдельном тестовом ПК и выделенным сервером. Проверьте аутентификацию до появления персонажа, отказ при прямом запуске незащищённого клиента, разрыв связи, освобождение места и повторный вход. Результат живой аттестации можно подтвердить только на настроенном развёртывании. [Чек-лист Epic](https://dev.epicgames.com/docs/epic-online-services/trust-and-safety/anti-cheat-interfaces/anti-cheat-integration-check-list).

## Сборка

В корне Unity-проекта рядом с **Assets** находится **com.playeveryware.eos-6.3.0.tgz**. В клоне получите его через **git lfs pull**. Манифест проекта ссылается на архив относительным путём. Для установки через редактор откройте **Window → Package Manager → + → Install package from tarball…** и выберите этот файл. В старых версиях Unity команда называется **Add package from tarball…**. Дождитесь импорта и компиляции. В верхней панели появится меню **EOS Plugin**.

Запускайте команды из корня проекта.

~~~powershell
.\Tools\Build-Raid.ps1
.\Tools\Build-Raid.ps1 -Protected
~~~

Первая команда собирает локальный клиент и сервер в изолированном проекте с одноразовыми приглашениями для игроков. Вторая использует установленный через UPM официальный EOS SDK 1.20.0.3 из пакета 6.3.0. Во временный проект помещается одна копия C# SDK и нативных библиотек x64 в виде встроенного пакета Unity. Игра инициализирует EOS и EAC со значениями из окружения процесса. Клиенту и серверу для подключения нужны параметры реального развёртывания Epic.

Для сборки со всей редакторской интеграцией пакета сначала задайте настоящее развёртывание Windows в **EOS Plugin → EOS Configuration**. Команда ниже сохраняет в копии проекта исходную зависимость от tarball и запускает штатную проверку sandbox ID и deployment ID. При этой сборке проверьте содержимое **Assets/StreamingAssets/EOS**: выбранная конфигурация попадает в плеер. Серверный секрет передавайте отдельно через окружение доверенного сервера.

~~~powershell
.\Tools\Build-Raid.ps1 -Protected -UsePluginConfig
~~~

Сервер и клиент для EAC находятся отдельно в **Build/Protected**. После настройки продукта запустите сервер через Build/Protected/Server/HeavyPocketsServer.exe с аргументами -batchmode -nographics. Игровой клиент запускайте через Build/Protected/Client/EACLauncher.exe. Обычный **Play.cmd** запускает локальную сборку с тестовыми приглашениями.

## Настройки процессов

Параметры передаются через отдельные окружения запуска. Выдавайте секрет доверенного сервера исключительно процессу выделенного сервера. Токен Epic каждого игрока получает доверенный механизм входа, который передаёт его соответствующему клиенту. Эта версия интеграции ожидает уже связанную с продуктом личность EOS Connect.

| Процесс | Переменные |
| --- | --- |
| Оба | HP_EOS_PRODUCT_ID, HP_EOS_SANDBOX_ID, HP_EOS_DEPLOYMENT_ID, HP_EOS_CLIENT_ID (идентификатор игрового клиента) |
| Только сервер | HP_EOS_SERVER_CLIENT_ID и HP_EOS_SERVER_CLIENT_SECRET из политики доверенного сервера, HP_RAID_CERT и HP_RAID_KEY с PEM-сертификатом и RSA-ключом для DTLS, HP_EOS_BIND_ADDRESS для сетевого интерфейса |
| Только клиент | HP_EOS_CLIENT_SECRET из клиентской политики, HP_EOS_EPIC_ID_TOKEN или HP_EOS_EPIC_ACCESS_TOKEN для одного игрока, HP_RAID_CA с публичным сертификатом доверенного центра, HP_EOS_TLS_HOST с DNS-именем сертификата сервера, HP_EOS_CONNECT_ADDRESS с адресом подключения |

Адрес по умолчанию — 127.0.0.1. Порт по умолчанию — 17777/UDP, его можно задать аргументом -port. Для удалённого теста настройте адрес привязки и доступ к выбранному порту. Системное хранилище сертификатов для локального плейтеста не требуется.

## Допуск в игру

- Клиент входит через EOS Connect, получает подписанный ID-токен и запускает Anti-Cheat Client в режиме ClientServer.
- Выделенный сервер проверяет токен в EOS. Он сверяет идентификаторы пользователя, продукта, sandbox, deployment и игрового клиента, затем регистрирует соединение в Anti-Cheat Server.
- До события **RemoteAuthComplete** соединение обменивается служебными сообщениями. Спавн, добыча, координаты игроков и команды рейда становятся доступными после подтверждения Epic.
- Отзыв подтверждения или требование **RemovePlayer** прекращает доступ к игровому состоянию и разрывает соединение. Тайм-аут также завершает вход. Это решение для текущей сессии, без автоматического постоянного бана.
- Игровой журнал приёмки отделён от служебного канала EOS. Он не записывает токены или содержимое сообщений аттестации.
